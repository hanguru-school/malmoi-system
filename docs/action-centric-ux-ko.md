# 행동 중심 UX（次の行動・今日やること・運営サマリー）

## 1. 목적

- **입력 기능 추가가 아니라**, 각 역할이 **지금 무엇을 해야 하는지 빠르게 판단**하고 **한 번의 클릭으로 이동**할 수 있게 한다.
- 기존 **AUTH_STORE_PATH, 세션, REST 경로, JSON 저장 형식**은 유지한다.

---

## 2. 행동 추천（학생 상세 / 선생 학생 상세）

### 구조

- `StudentRecentFlowSummary` 하단에 **「次の行動」** 영역을 두고, 역할별 링크를 표시한다.
- **관리자**: `次回レッスンを確認` → `/admin/reservations?studentId=` など（予約・ノート・宿題・予約状況）。
- **先生**: `次回レッスンを確認` → `/teacher/today`、他は `studentId` 付きでレッスンノート・宿題・当日スケジュール。

### 주요 동선

1. 学生詳細または先生の学生サマリーを開く  
2. 要約を読む → すぐ下のボタンで目的画面へ  

### 롤백

- `StudentRecentFlowSummary.js` と `student-detail.module.css` の該当ブロックを削除すれば、要約のみに戻せる。

### 운영 주의

- リンクは **読み取り専用要約と独立**しており、権限は既存の各ページに従う。

---

## 3. 先生ホーム「今日やること」カード

### 구조

- `/teacher` で **ナビより上**に **「今日やること」** セクションを配置。
- KPI カード:
  - 本日の担当レッスン件数 → `今日のレッスン` へ
  - ノート未作成（**本日・完了済み**レッスンの lessonUnitId 基準）
  - 宿題未登録（**本日・完了**かつ `lessonUnitId`+`studentId` に対し、当日 `lessonDate` の宿題が無い件数）
  - 提出待ち宿題（全体の `submitted` 件数）→ 宿題管理へ
- **最近のお知らせ**（最大3件）と `お知らせ一覧へ` リンク。

### 주요 동선

先生がログイン → まず数値とリンクで **今日の優先作業**を把握 → ナビ・メニューへ。

### 롤백

- `app/teacher/page.js` を以前のレイアウトに戻し、`teacher.module.css` の `.todayPriority` 系を削除。

### 운영 주의

- 「宿題未登録」は **当日完了したレッスン**に紐づく宿題の有無で推定。運用ルールとずれる場合は文言・条件を調整する。

---

## 4. 学생ホーム「次の一手」条件형

### 우선순위（1つだけ `data-emphasis="high"`）

1. **未完了の宿題** → 宿題タイル強調  
2. **次の予約日が今日から3日以内** → 予約タイル強調、文言 **「次の予約を確認」**  
3. **次の予約が無い** → 予約タイル強調、**「予約する」**  
4. **直近ノートあり** → ノートタイル強調  

### 롤백

- `StudentDashboard.js` の `retentionFocus` 計算と予約タイルの文言分岐を元に戻す。

### 운영 주의

- 「3日以内」は `todayYmd` と次回予約の `date` の日差で算出（ブラウザローカル日付と整合するようサーバが JST 基準で渡す前提）。

---

## 5. 管理ダッシュボード「運営サマリー」カード

### 구조

- `/admin` 最上段に **4カード**（読み取り専用）:
  - 本日の予約件数 → 日付付き予約一覧  
  - 登録進行中学生数（`listStudentsForAdmin` pageSize 500 ベースで未完了登録をカウント）  
  - 最近のお知らせ（公開中・最大3行）  
  - 最近の監査ログ（最大4行）→ `#admin-recent-audit` へ  

### 롤백

- `app/admin/page.js` の `opsSummaryStrip` セクションと `admin.module.css` の `.opsSummary*` を削除。`listStudentsForAdmin` の pageSize を元に戻す。

### 운영 주의

- 登録進行中人数は **一覧取得件数内**で正確。学生数が極端に多い場合はページング方針を別途検討。

---

## 6. 배포

- `npm run build` 成功後、既存手順でサーバへ反映。
