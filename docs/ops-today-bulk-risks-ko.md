# 본일 미처리 업무 화면 · 일괄 처리 · 학습 시그널 (운영 문서)

## 1. 목적

- **무엇을 해야 하는지**만 보여주는 단계에서 한 단계 나아가, 선생·관리자가 **미처리 업무를 더 빨리 닫을 수 있게** 한다.
- 화면 이동 클릭 수를 줄이고, 숙제 확인처럼 반복 작업은 **최소한의 일괄 처리**로 줄인다.
- 학생별로 **참고용 위험/학습 시그널**을 읽기 전용으로 노출해 우선 순위 판단을 돕는다.

---

## 2. 오늘 기준 미완료 업무 화면 (`/teacher/ops-today`, `/admin/ops-today`)

### 2.1 역할

| 경로 | 대상 |
|------|------|
| `/teacher/ops-today` | 선생 (담당 범위) |
| `/admin/ops-today` | 관리자 (전체) |

### 2.2 포함 항목 (요약)

- **오늘 완료된 수업 중 레슨 노트 미작성** → 노트 작성 화면으로 링크 (`lib/ops/todayBacklog.js`의 `buildTeacherTodayBacklog` / `buildAdminTodayBacklog`).
- **오늘 완료된 수업 중 숙제 미등록** → 숙제 화면으로 링크.
- **제출 확인 대기 숙제** (`status === submitted`) → 숙제 상세/목록으로 링크.
- **예약 관련 미처리**
  - 선생: 담당 **`change_requested`** 예약 → 스케줄 화면 등.
  - 관리자: **`requested`(승인 대기)**, **`change_requested`(변경 요청)** → 예약 관리 등.

### 2.3 주요 동선

1. 선생: **선생 홈** 또는 상단 내비 **「本日の未処理」** → 각 섹션에서 해당 링크 클릭 → 기존 화면에서 처리.
2. 관리자: **관리 대시보드** 상단 운영 요약 카드 **「抜け・提出待ちをまとめて見る」** 또는 내비 **「本日の未処理」** → 동일.

### 2.4 롤백 방법

- 해당 라우트만 제거하거나 내비/대시보드 링크만 숨기면 UI 접근은 차단 가능하다.
- 비즈니스 로직은 `lib/ops/todayBacklog.js`에 집중되어 있어, **표시 전용**이므로 스토어/JSON 스키마 변경은 없다.

### 2.5 운영 주의점

- **오늘(JST)** 기준 날짜는 `todayYmdJst()`로 통일한다.
- 목록/페이지 크기 제한으로 인해 극단적으로 많은 예약·숙제가 있을 때 **일부만 표시**될 수 있다. 필요 시 `todayBacklog.js`의 `slice` 상한을 조정한다.
- 관리자 화면의 링크는 기존 `/admin/homework`, `/admin/lesson-notes`, `/admin/reservations` 등 **기존 경로**를 유지한다.

## 3. 일괄 처리 액션

### 3.1 구현 요지

- **제출된 숙제**를 여러 건 선택해 **「確認済み」(reviewed)** 로 일괄 변경한다.
- API: `POST /api/admin/homework/bulk-status` (기존 유지).
- UI: `app/components/ops/SubmittedHomeworkBulkBar.js` — 본일 미처리 화면의 「提出確認待ち」 섹션 하단에 배치.

### 3.2 주요 동선

1. 본일 미처리 → 「提出確認待ちの宿題」에서 항목 선택 → **「確認済みに一括更新」**.
2. 성공 시 페이지를 새로고침하여 목록을 갱신한다.

### 3.3 롤백 방법

- `SubmittedHomeworkBulkBar` 사용처에서 컴포넌트 제거만으로 UI 롤백 가능.
- API는 그대로 두고 UI만 숨기는 것이 가장 안전하다.

### 3.4 운영 주의점

- **상태 값**과 권한(관리자/선생)은 기존 API 정책을 따른다. 잘못된 일괄 확정을 막으려면 운영 규칙(예: 반드시 내용 확인 후 버튼)을 팀 내에서 통일한다.
- 선생·관리자 모두 동일 API를 호출하므로, **권한이 없는 역할**에서는 403이 나올 수 있다. 그 경우 개별 숙제 화면에서 처리한다.

## 4. 학생별 위험 신호(학습 시그널)

### 4.1 데이터 소스

- `lib/auth/store.js`의 **`summarizeStudentRisksForAdmin(studentIds)`** — JSON 스토어를 읽어 **배지 목록만** 반환 (스키마 변경 없음).

### 4.2 표시 위치

| 위치 | 내용 |
|------|------|
| 관리자 학생 상세 | `StudentRiskStrip` (기존) |
| 관리자 학생 목록 V2 | 테이블 열 **「学習シグナル」** — 초기 페이지 로드 시 `summarizeStudentRisksForAdmin`으로 채움 |

### 4.3 신호 예시 (비고)

- 예약 공백이 길다 / 예약 이력이 약하다  
- 미완료 숙제 누적  
- 최근 레슨 노트 없음(30일 등)  
- 노트 텍스트 내 **주의 키워드** 반복(참고용)

### 4.4 롤백 방법

- `summarizeStudentRisksForAdmin` 호출 및 UI 열 제거로 읽기 전용 표시만 중단 가능.
- 스토어 필드 추가 없음.

### 4.5 운영 주의점

- **의료/법적 판단이 아닌 참고용**이다. 라벨은 일본어 UI 유지.
- 학생 목록 V2에서 **검색·페이지 전환으로 클라이언트가 새 목록을 가져온 경우**, 시그널은 **초기 서버 렌더 시점의 ID에 대해서만** 채워질 수 있다. 새로 나온 행에는 배지가 비어 있을 수 있으므로, 확정 판단은 **학생 상세**를 본다.
