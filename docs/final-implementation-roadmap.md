# MalMoi Portal Final Implementation Roadmap

## 0. 문서 목적
- 본 문서는 MalMoi Portal의 최종 구현 순서, 의존관계, 테스트/배포 기준을 실행 가능한 단위로 고정한다.
- 기준 원칙:
  - 한 번에 전부 만들지 않는다.
  - 운영 필수 기능을 먼저 안정화한다.
  - 학생/관리자/예약/레슨노트를 우선 완성한다.
  - 확장 기능은 구조만 먼저 연결하고 세부 고도화는 후순위로 둔다.

---

## 1. 전체 단계(Phase) 구성

### Phase 0 - 기반 안정화
- 목표:
  - 운영 환경과 배포 흐름 표준화
  - URL/인증/메일 링크 기준 단일화
- 작업:
  - `portal.hanguru.blog` 기준 URL 정리
  - `.env` 항목 정규화 (auth/mail/base URL)
  - 빌드/재시작 절차 고정 (`build -> restart -> health-check`)
  - systemd/cloudflared 점검
  - SUPER ADMIN 초기 계정 보장
- 완료 기준:
  - 재부팅 후 자동복구 + 로그인/인증링크 정상

### Phase 1 - 로그인/회원가입/포털 골격
- 목표:
  - 학생/관리자/보호자 진입선 완성
- 작업:
  - 로그인 UI/동선 통일
  - 학생 등록 단계 플로우 안정화
  - 메일 인증 후 단계 접근 제어
  - 비밀번호 재설정 플로우 정리
- 완료 기준:
  - 학생 등록/로그인, 관리자 로그인, 보호자 로그인, 비밀번호 재설정 가능

### Phase 2 - 학생/관리자 핵심 화면
- 목표:
  - 학생 홈과 관리자 대시보드를 실제 운영용으로 완성
- 작업:
  - 학생 홈/개인정보/공지/예약 진입
  - 관리자 대시보드/학생목록/학생상세 기본 탭
- 완료 기준:
  - 로그인 직후 핵심 업무 화면으로 즉시 이동 가능

### Phase 3 - 예약 시스템 안정화
- 목표:
  - 예약을 운영 핵심 프로세스로 완성
- 작업:
  - 학생 예약 생성/변경/취소
  - 관리자 예약 목록/상태변경/상세패널
  - 리스트형 + 시간표형 정리
  - 예약-학생상세, 예약-레슨노트 연결
  - 1:1/페어/그룹 구조 정리
- 완료 기준:
  - 학생 예약 가능 + 관리자 상태관리 가능 + 레슨노트 작성 흐름으로 연결

### Phase 4 - 레슨노트/숙제/학습 흐름
- 목표:
  - 수업 후 학습 사이클 완성
- 작업:
  - 레슨노트 목록/작성/공개
  - 학생/보호자 노트 확인
  - 숙제 생성/상태관리
  - 학생/보호자 숙제 화면
  - 노트 -> 숙제 연결
- 완료 기준:
  - `수업 완료 -> 노트 작성 -> 공개 -> 숙제 연계`가 단절 없이 동작

### Phase 5 - 보호자/메일/공지 고도화
- 목표:
  - 커뮤니케이션 운영 체계 완성
- 작업:
  - 보호자 홈 + 자녀 단위 메뉴 정리
  - 공지 작성/공개/열람 개선
  - 메일 이력/템플릿/재발송/연결 알림 정리
- 완료 기준:
  - 보호자 사용 가능 + 공지 전달 가능 + 메일 추적 가능

### Phase 6 - 통계/시스템설정/운영안정화
- 목표:
  - 학습관리 플랫폼 수준으로 확장
- 작업:
  - 학생/관리자/보호자 통계
  - 시스템 설정(예약/수업/메일/보안)
  - 설정 변경 로그, 운영 알림/장애 추적
- 완료 기준:
  - SUPER ADMIN이 운영 기준값 조정 가능, 문제 추적 가능

## 2. 운영 가능 최소 단계(MVP 운영 기준)

### 운영 시작 최소 조건
- 학생 로그인 가능
- 관리자 로그인 가능
- 학생 등록 가능
- 예약 생성/관리 가능
- 레슨노트 작성/공개 가능
- 공지 전달 가능

### 판정
- 위 조건 충족 시점을 **운영 개시 시점 (Operational MVP)** 으로 정의한다.
- 본 로드맵 기준으로는 **Phase 4 완료 시점**에 Operational MVP 달성.

---

## 3. 기능 의존관계(고정 순서)

1) 인증/가입  
2) 학생/관리자 기본 포털  
3) 예약  
4) 레슨노트  
5) 숙제  
6) 보호자  
7) 메일 관리  
8) 공지 고도화  
9) 통계  
10) 시스템 설정 고도화

### 강제 규칙
- 예약 전에 레슨노트를 완성하지 않는다.
- 학생 기본 흐름 안정화 전 보호자 기능 확장 금지.
- 시스템 설정은 기능 기반이 안정된 뒤 정책 제어를 붙인다.

---

## 4. 테스트 계획(Phase Gate)

각 Phase 완료 시 아래 시나리오를 누적 회귀 테스트한다.

1. 학생 신규 등록  
2. 학생 로그인  
3. 관리자 로그인  
4. 예약 생성  
5. 예약 변경/취소  
6. 레슨노트 작성/공개  
7. 학생 노트 확인  
8. 공지 작성/열람  
9. 메일 발송/로그 확인  
10. 서버 재시작 후 정상 복구

### Gate 규칙
- 현재 Phase + 이전 Phase 시나리오가 모두 통과해야 다음 Phase 진행.
- 서버 반영 후 smoke test 완료까지를 "완료"로 본다.

---

## 5. 배포/반영 기준

### 표준 반영 절차
1. Cursor 코드 수정
2. 서버 업로드
3. 서버 build
4. 서비스 restart
5. `portal.hanguru.blog` 실접속 검증

### 완료 정의
- "코드 작성 완료"가 아니라 **"서버 반영 + 실동작 확인 완료"** 를 완료로 정의.

## 8. 나중에 붙여도 되는 기능(후순위)

- 고급 통계 시각화(심화 대시보드)
- 메일 템플릿 고급 편집기(동적 변수/버전관리)
- 보호자 포인트/정산 고도화 리포트
- 운영 로그 분석 자동화(알림 룰 엔진)
- 공지 대상 세분화/세그먼트 발송 최적화

원칙: 운영에 직접 영향이 적은 확장 기능은 Operational MVP 이후 단계적으로 추가.

---

## 9. 실행 운영 방식(실무용)

- 1주 단위 Sprint로 운영:
  - 월: 상세 작업 분해
  - 화~목: 구현 + 단위 검증
  - 금: 통합 테스트 + 서버 반영
- 각 Sprint 종료 시:
  - 완료 기능
  - 미해결 이슈
  - 다음 Sprint 선행조건
  를 문서화하여 누적 관리.
